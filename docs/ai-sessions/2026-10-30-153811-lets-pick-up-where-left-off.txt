  property passing to family. Of the 11,199 sales it would count, only about

  There are three ways to fix it:

     a trigger. Estate means an executor, fiduciary, administrator, trustee,
     survivorship, transfer-on-death or will-book deed, at any price. That's

     aging signal you're after, and it doesn't rely on an unevenly applied code.
     Code 37 on an ordinary deed would fall to other. Estate still wins over

     steadily from 224 in 2012 to 330 in 2025. It answers your question most

  (docs/superpowers/specs/2026-10-30-analytics-layer-design.md). It now uses

  - An estate deed coded love and affection, or priced at $10 or less, is
    estate_family.
  - Any other estate deed, and any sale coded 37, is estate_sale.
  - family is love and affection on an ordinary deed.

  The output view, analytics.family_transfers_by_year, has one row per year for
  2012–2025 with these columns:
  - all transfers
  - family transfers, as a count and a share
  - estate-to-family transfers, as a count and a share
  - unanalyzed transfers

  These are the calls I made myself. Please check them as you read; they're also
  listed at the end of the spec:

  1. Estate deeds are fiduciary, executor, administrator, trustee, survivorship,
     affidavit of survivorship, transfer-on-death and will-book deeds.
     Survivorship is included even though it's usually spouse to spouse.
  2. "For nothing" means coded love and affection or priced at $10 or less. A
     missing price doesn't count as nominal.
  3. Code 37 only ever makes a sale estate_sale, because the assessor applies it
     unevenly over the years.
  4. Other classes from the sale code: market is codes 0 and PV. distressed is
     sheriff, treasurer, court-ordered, previous foreclosure, short sale and
     bank. Everything else is other.
  5. Unanalyzed years stay in. 2012, 2018 and 2019 are kept, with the
     not_analyzed_transfers column and a README note explaining that family
     counts for those years are probably low.
  6. 2026 is left out by a rule, not a hard-coded year: only years before the
     year the data was downloaded are shown.
  7. Two new data-quality flags, each alerting on its first failure: a sale code
     missing from the mapping, and a parcel whose municipality or school
     district changes between sales. Both are 0 today.
  8. Build details:
     - The code-to-class mapping lives in a Python module,
       wprdc/sale_classes.py.
     - Tables use the source's own codes as keys.
     - A parcel's address comes from its latest sale.
     - python -m wprdc.analytics is its own step, built in one transaction.
     - The wprdc.pipeline command is a separate task.

● This is a small change, so here's the design in brief before I build it.

  python -m wprdc.pipeline runs the four steps in order, each through its own
  existing main():

  1. ingest: fetches the CSV from CKAN, or skips the download if CKAN says the
     data hasn't changed.
  2. load_raw: loads any new file as a raw snapshot.
  3. transform: builds the staging and clean tables and runs the data-quality
     checks.
  4. analytics: builds the star schema and prints the output table.

  - Stops at the first failure. The failed step is already recorded in
    ops.fetch_run, as now, and the error is passed on so the command exits
    non-zero. Later steps don't run, so the previous clean and analytics tables
    stay as they were.
  - Re-runnable. Every step already does nothing when there's nothing new.
    Running the pipeline twice in a row skips the download, loads nothing,
    re-evaluates nothing and rebuilds identical analytics tables.
  - Options: just --force, passed to ingest, to download even when the data
    hasn't changed. The other steps' special modes stay on their own commands:
    --strategy datastore, --prune-keep, --rebuild. My call: the one command is
    for the normal run, and the README can point to the special modes.
  - No extra run record for the pipeline itself, since each step already logs
    its own run.
  - Tests:
    - the steps run in order, and --force reaches ingest
    - a failing step stops the steps after it
    - an end-to-end run with the network call replaced by a local CSV
